## 🌍 概要

Pythonの練習用に作っている、**ターミナルで動くパーティ制のターンバトルRPG**です。
**標準ライブラリだけで動く**ので、Pythonが入っていればすぐに遊べます。

勇者と戦士のパーティで魔物の群れを倒し、休息と準備をしてからボスのドラゴンに挑みます。

---

## ✨ 特徴

| | 機能 | 内容 |
|:-:|---|---|
| ⚔️ | **ターン制バトル** | ラウンドごとに素早さの順で行動する |
| 🔮 | **魔法 5種** | 攻撃・状態異常・回復・治療・蘇生 |
| ☠️ | **状態異常 3種** | 麻痺・毒・火傷（継続ダメージ／行動不能／攻撃力低下） |
| 🎒 | **共有インベントリ** | パーティ全員で同じアイテムを使う |
| 📈 | **レベルアップ** | 経験値でHPと攻撃力が上がる |
| 🤖 | **敵ごとのAI** | 狙う相手の選び方・技の選び方が敵によって違う |
| 🏕️ | **ステージ間の休息** | 次の戦闘の前に回復と準備ができる |
| 🧩 | **データ駆動** | アイテム・技・状態異常・成長値を辞書で定義 |

## 🚀 クイックスタート

### 必要なもの

- Python **3.9** 以上（`tuple[bool, int]` の型ヒントを使っているため）
- 外部ライブラリは不要

### 起動

~~~bash
git clone https://github.com/your-name/your-repo.git
cd your-repo
python 1_main.py
~~~

### 操作方法

すべて**数字を入力して Enter** で操作します。`-1` を入力すると1つ前の選択に戻れます。

| 入力 | 戦闘中の行動 |
|:---:|---|
| `0` | 攻撃 |
| `1` | アイテム |
| `2` | 魔法 |
| `3` | 防御（受けるダメージが半分になる） |

## ⚙️ ゲームシステム

### ターン処理

1. ラウンドの最初に、生きているキャラを**素早さが高い順**に並べる
2. 自分のターンが来ると、防御が解除される
3. かかっている状態異常のダメージを受け、残りターンが1減る
4. 麻痺していなければ行動する

### ダメージ計算

~~~text
基本ダメージ = 攻撃力 × 火傷補正 × (1 + 乱数(-25%〜+25%))
クリティカル = 20% の確率でダメージ2倍
防御中       = ceil(ダメージ ÷ 2)
~~~

### 魔法

| 魔法 | MP | 対象 | 効果 |
|---|:-:|:-:|---|
| 🔥 ファイア | 10 | 敵 | 1.3倍のダメージ。30%の確率で**火傷**（3ターン） |
| 🧪 ポイズン | 6 | 敵 | 0.5倍のダメージ。必ず**毒**（3ターン） |
| 💚 ヒール | 8 | 味方 | HPを50回復 |
| ✨ キュア | 5 | 味方 | 毒を治す |
| 👼 リザレクト | 15 | 倒れた味方 | 最大HPの50%で生き返らせる |

### 状態異常

| 状態 | 毎ターンのダメージ | 追加効果 |
|---|:-:|---|
| ⚡ 麻痺 | 5 | **行動できない** |
| ☠️ 毒 | 15 | なし |
| 🔥 火傷 | 8 | **攻撃力が0.5倍** |

すでにかかっている状態異常をもう一度受けた場合、残りターンは長いほうになります（重ねがけで延びることはありません）。

### アイテム

| アイテム | 効果 | 最初の所持数 |
|---|---|:-:|
| 回復薬 | HPを30回復 | 3 |
| 上級回復薬 | HPを60回復 | 1 |

### レベルアップ

- 次のレベルまでに必要な経験値 = **現在のレベル × 30**
- 1レベル上がるごとに **最大HP +20** と **攻撃力 +4**
- 経験値は、戦闘の最後に**生き残っていた仲間だけ**がもらえる

<br>

技は重み付きの抽選で決まります。重みは**自分の残りHPの割合**で変わります。

**スライム**：追い詰められるほど特殊な技を使いやすくなる

| 技 | 効果 | 重み（HP満タン → HP0） |

| 技 | 効果 | 重み |
|---|---|:-:|
| 攻撃 | 通常のダメージ | 5 |
| 体当たり | 1.1倍のダメージ | 5 |
| 炎のブレス | 1.4倍のダメージ ＋ 50%で火傷 | HP50%以上なら0、未満なら8 |

## 🏗️ 設計

### クラス構成

~~~mermaid
classDiagram
    Player <|-- Hero
    Player <|-- Monster
    Hero --> Inventory : 共有

    class Player {
        +hp / maxhp
        +attack_power / speed
        +status
        +attack()
        +take_damage()
        +check_debuff()
    }
    class Hero {
        +mp / level / exp
        +input_func
        +choose_action()
        +gain_exp()
        +rest()
    }
    class Monster {
        +attacks
        +target_selector
        +attack_chooser
        +act()
        +use_skill()
    }
    class Inventory {
        +items
        +use()
    }
~~~

### 設計で意識していること

- **処理を外から渡せるようにしている**
  - `Hero(input_func=...)`：入力処理を差し替えられる。テストでは、決まった順番で値を返す関数を渡せる
  - `Monster(target_selector=..., attack_chooser=...)`：敵のAIを関数で入れ替えられる（ストラテジーパターン）
- **データとロジックを分けている**
  - 状態異常は `status_definitions` に1件追加するだけで増やせる
  - 成長値・休息の回復量・MP消費は `level_settings` / `rest_settings` / `magic_mpcosts` で調整できる
- **ステージを差し替えられる**
  - `run_adventure()` に渡すステージのリストを変えるだけで、冒険の構成を変えられる

### テストの例

~~~python
def test_defend_halves_damage():
    hero = Hero("勇者", 100, 0, 10, Inventory({}))
    hero.defend()
    hero.take_damage(15)

    assert hero.hp == 92  # (15 + 1) // 2 = 8


def test_choose_defend_by_scripted_input():
    inputs = iter([3])  # 3: 防御
    hero = Hero("勇者", 100, 0, 10, Inventory({}), input_func=lambda _: next(inputs))

    assert hero.choose_action([], [hero])
    assert hero.is_defending
~~~
